# 比例记录（Scale Record）

> 由 `tokyo/scale_record.py` 生成；层数取自各资产 `vol.npy`，真实高度取自 `tokyo/scale_data.py`。
> 要改比例：先改 `scale_data.py`，再重跑 `scale_record.py` 与 `make_index.py`。

## 1. 基准比例

- **12 px/m** → **1 像素 = 8.33 cm**，1 米 = 12 像素。
- 落在基准（±15% 以内）的资产：**382** 个 —— 可任意混搭，人物/车辆/建筑相对尺寸真实。
- 压缩比例的资产：**19** 个 —— 独立摆件，不可与基准直接混搭（见第 3 节）。
- 角色摆件：**3** 个（初音 S/M/L，自带分辨率）。

## 2. 为什么不能全部同比例

层数 = 真实高度 × 12；高层地标在单机上不可行：

| 地标 | 真实高 | 12px/m 需要的层数 |
|---|---|---|
| 02_skytree | 634 m | 7608 |
| 01_tokyo_tower | 333 m | 3996 |
| 22_abeno_harukas | 300 m | 3600 |
| 29_akashi_bridge | 298 m | 3576 |
| 07_roppongi_midtown | 248 m | 2976 |
| 06_roppongi_mori | 238 m | 2856 |

所以这些采用**压缩比例**建模（保住轮廓与细节），作为独立摆件展示。

## 4. 混搭换算

```
放大倍数 = 12 / 该资产实际 px/m
```

例：晴空塔 1.50 px/m → 需放大 **8 倍**；放大后高 7608 像素，不会放进普通场景。

**建议**：压缩资产只作独立展示；若确需同场景，采用分级 LOD（远景小比例 / 近景 12px/m 局部）。

## 5. 角色摆件（3 个）

初音未来 S/M/L：自带 `px_per_m`（见各自 `params.json`），约 1.5 m 高，属角色摆件，不参与建筑场景混搭。

## 6. 目录页显示规则

- 基准资产：`~N m`（N = 层数 / 12）
- 压缩资产：**`实高 N m`** + **`压缩 1:K`**（不再显示按 12px/m 折算的假高度）
- 角色资产：`~1.5 m` + 实际 `px/m`
