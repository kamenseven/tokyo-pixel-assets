# 制作过程对比：旧方法 vs 新方法（为什么旧的好）

对比对象：`tokyo/more/12_museum`（旧：`tokyo/more_b3.py:184` `museum()`）与新 recipe `tokyo/recipes/new_12_museum.json`。

## 旧方法实际做了什么（代码级）

1. **体量**（约 6 个 box/box2）：石基座、中部悬挑体、顶部玻璃体、薄铝压顶。
2. **接缝阴影**（2 个 STEEL_D 薄盒）：在体块交接处做 0.4m 阴影缝 → 体块"分层"。
3. **入口组件**：玻璃门 + 铝雨棚 + 2 根金属柱 + 招牌带。
4. **广场道具**：沥青地坪 + 12 个列柱（`np.arange` 阵列）+ 雕塑基座 + 2 段 cap 组成 Λ 形雕塑 + 球体 + 2 个花池(带 GREEN 灌木) + 长椅 + 椅基。
5. **`M.shade()`** → 法线光照分 4 档。
6. **贴花层（关键）**：
   - 汉字招牌 `_kanji`
   - 石材板缝：4 个面的 `_hlines` + `_vlines`（每 1.2m/2.4m 一条）
   - 基座带状窗：`M.windows("front", …)`、`M.windows("left", 0,0, y范围, …)`（**侧面传的是 y 范围**）
   - 中部连续带窗：`M.front(...)` + `M.right(...)` + 竖梃 `_vlines` + 铝亮线
   - 顶部玻璃幕墙网格：4 个面 `_vlines` + `_hlines`
   - 入口门轨、雕塑高光
7. **hollow**：显式挖掉 carve 会填实的空腔。

> 结论：旧资产的"好看"主要来自 **第 3/4/6 步——道具 + 贴花层**，体量本身只有 6 个盒子。

## 新方法实际做了什么（recipe 级）

`new_12_museum.json`：**95 个 box2 + 3 个 ell，windows=0，decals=0**。
= 只有第 1 步（体量），没有阴影缝、入口组件、广场道具、任何贴花/窗户。

## 根因（4 条）

1. **细节层缺失（主因）**：旧方法在体量之上有"贴花层 + 道具层"；新 recipe 只写了体量。`windows` 条目少且 rows/cols 低（2~3 行），立面成为大色块。
2. **侧面窗传参错误**：`windows` 的 `face=left/right` 要的是 **y 范围**，但多数新 recipe 传了 `x=[0,0]` → 侧面窗几乎没画出来（3/4 立面是空的）。
3. **分辨率不匹配（次因）**：武道馆 186 vs 旧 369（0.50）、塔楼公寓 313 vs 650（0.48）、大阪城 275 vs 456（0.60）、机场 406 vs 499、Big Sight 339 vs 381、车库 181 vs 207。**部分 recipe 写了显式 `grid`，改 `scale` 不生效**，导致分辨率固死在半精度。
4. **无道具/无材质层次**：旧方法有花池、长椅、雕塑、招牌、接缝阴影线；新 recipe 基本没有，且很少用自定义 ramp。

## 优化措施（已实施）

1. **新增 compound op `facade`**（`ops_extra.py`）：一次调用画完 窗格 + 竖梃(mullion) + 楼层线(course) + 转角石(quoins) + 窗台(sill)。正是旧 `_hlines+_vlines+windows+quoins` 组合的固化。
2. **新增 `dormers`**：屋顶老虎窗阵列。
3. **`enrich_recipes.py`**：把已有 `windows` 自动升级为 `facade`（并修复 left/right 的 y 范围回退到主体 y 范围）；无窗资产自动按主体尺寸生成 4 面玻璃网格。
4. **分辨率对齐**：grid-aware 缩放 —— 对写死 `grid` 的 recipe 同步放大 grid，使 slices ≈ 旧资产。
5. **单位坑**：`decals` 默认像素（可 `units:"m"`），`windows` 是米。
